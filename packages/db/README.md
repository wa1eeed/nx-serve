# @nxserve/db

The database layer: SQL migrations (the source of truth), the migration runner, the role aware
connection helpers, seeds, and the Row Level Security isolation test suite.

## Responsibility

- **Migrations** (`migrations/*.sql`): the reference schema converted with the docs/04 rules and the
  docs/25 capability blocks. UUIDv7 primary keys generated by the application, money as `bigint`
  minor units with a currency, translatable text as `jsonb {en, ar}`, tenant scoped unique keys,
  composite `(tenant_id, id)` foreign keys on hot relationships, FORCE RLS with USING and WITH CHECK
  on every tenant table, audit/outbox/idempotency tables, monthly partitioning for the high volume
  logs, and the stops model and payment plans (ADR-0014).
- **Roles**: migrations run as the owner; the API connects as the non owner `nxserve_app` role (RLS
  enforced); the `nxserve_superadmin` role has BYPASSRLS and is used for reference seeds and the
  platform admin backend, audited.
- **Helpers**: `createPool(role)` and `withTenant(pool, tenantId, fn)` which sets
  `app.tenant_id` via SET LOCAL inside a transaction so RLS scopes every statement.

## Commands

- `pnpm --filter @nxserve/db migrate` applies pending migrations (owner role).
- `pnpm --filter @nxserve/db reset` drops and recreates the schema, then migrates and seeds.
- `pnpm --filter @nxserve/db seed` seeds reference and demo data (super admin role).
- `pnpm --filter @nxserve/db pull` generates `src/schema.ts` (Drizzle) from the migrated database.
- `pnpm --filter @nxserve/db test` runs the RLS isolation suite against a throwaway PostGIS
  container (Testcontainers). This suite blocks merges (CLAUDE.md).

Local Postgres runs via `docker compose -f infra/compose/docker-compose.yml up -d postgres` on host
port 5544 (5432 is often taken by a native Postgres).

## Isolation guarantee

`rls-isolation.test.ts` proves, exhaustively, that every table carrying `tenant_id` has FORCE RLS
and a policy with both USING and WITH CHECK, and proves behaviourally on the core path that the app
role cannot read, insert or update another tenant's rows, and that an unset tenant denies everything.

## Tables owned

All of them; other packages reach the database only through the API's repositories, never directly.
